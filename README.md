# Rental Scan

一套跑在 Muse 技能（skill）上的租房筛客工作流：房东把一套房挂到 Facebook 租房群和小红书之后，剩下的"每天翻新帖、挑出对口的求租人、逐个联系、记台账"交给助理自动完成，房东只做两个动作——看汇总、点头联系。

> 这是**脱敏公开版**：只分享方法与工具。真实账号、群组/帖子 ID、房源细节、客户数据与照片不包含在本仓库中（见文末"隐私边界"）。

## 每天怎么运转

1. **自动扫描**（每天上午，云端）：只看前一天 00:00–23:59 的新内容。
   - **Facebook**（facebook-cli）：已加入的租房群里——发帖找房的人（A 类）、出租帖下留言问价的人（B 类）、自己房源帖下的新评论（C 类）。
   - **小红书**（网页版）：几个租房关键词的最新笔记——"人找房"帖主（A 类）、"房找人"帖下的意向评论者（B 类）、自己帖子的新评论与私信咨询（C 类）。若房源有性别限制（如仅限男生），候选人逐个打开主页核实性别，符合才入选。
2. **匹配与去重**：需求与房源事实逐项比对（区域、预算、租期、人数、性别等硬条件不合直接排除；没写全的标"待确认"）；与 Excel 台账比对，同一个人只联系一次。
3. **一条汇总**：新客户先登记台账（状态"待联系"），然后给房东发一条消息：Facebook 可联系 N 人、小红书可联系 M 人，每人一句话需求摘要。
4. **联系（房东点头后才做）**：
   - Facebook 私信：助理在房东的电脑上新开一个浏览器窗口代发（文字 + 全部房源照片），再在原帖下补一句公开的"已私信"指针回复。
   - 自己帖子下的评论：云端直接回复（每条经房东确认）。
   - 小红书私信：网页版没有给陌生人发私信的入口，所以助理交付清单（昵称 + 小红书号 + 统一文案），房东在手机 App 里发送。
5. **记账**：联系结果用脚本更新进 `Rental Scan.xlsx` 并回传房东电脑，校验一致才算完成。

**红线**：谈判（价格、租期、入住日期、家具等任何具体承诺）一律先报房东，助理不自动承诺；单轮私信超过 10 条先停下问房东。

## 仓库结构

| 路径 | 内容 |
|---|---|
| `SKILL.md` | 技能本体：房源事实模板、匹配标准、三类客户定义、文案模板、操作流程与实测经验（**流程以此为准**） |
| `tools/rental_log.py` | 台账脚本：Excel 台账的增删改查只能走它，不手工逐格编辑（依赖 `openpyxl`） |
| `ledger_template.csv` | 台账的列名模板（真实台账是带备注行与超链接的 Excel，由脚本生成维护） |
| `.gitignore` | 忽略 Python 缓存、真实台账、照片与本地配置等 |

## 几个实测结论（踩过的坑）

- Facebook 的接口拿不到"别人帖子下评论"的作者信息，所以 FB 的 B 类暂时只能发现、无法联系到本人；小红书网页版能看到评论者昵称，B 类可行。
- 云端浏览器登录 Facebook 后，Messenger 的端到端加密 PIN 还原会死循环，私信发不出去——FB 私信只能走房东本机浏览器代发这一条路。
- 小红书第三方爬虫的 API 登录会被其安全接口风控（数据中心 IP 直接断连）；网页版扫码登录则稳定可用。
- 在 Facebook 私信框里可靠输入文字的方法是先用 foreground 点击取得真实键盘焦点再打字；普通填充和 Tab 都会把字打错地方。

## 隐私边界

本仓库刻意**不包含**：真实客户台账（姓名 + 主页链接属于他人个人信息）、房源照片、任何平台的账号 ID / 小红书号、群组与帖子 ID、房源地址与租金、本地文件路径。这些只存在于使用者的本地工作副本中。若你 fork 本项目自用，请同样只把脱敏后的方法文件放进公开仓库（`.gitignore` 已默认忽略 `*.xlsx`、`Photo/` 与 `local_config.*`）。

## 使用方式

这是一个 Muse 技能：在你的技能目录放入 `SKILL.md` 与 `tools/`，按文中的模板填好自己的房源事实、监控群组与帖子清单，再配一个每日定时任务即可。细节全部写在 `SKILL.md` 里。

```bash
pip install openpyxl
python3 tools/rental_log.py --file "Rental Scan.xlsx" list
```
